**Goal:** Upgrade lua-simdjson from bundled simdjson 5.0.5 to 5.1.1, investigate issue #117 on native Windows GitHub Actions, fix only demonstrated defects, and submit an evidence-backed upstream PR.

**Spec:** The user-approved scope is recorded in Global Constraints and Acceptance Criteria below; this plan is self-contained. Initial investigation: https://github.com/FourierTransformer/lua-simdjson/issues/117.

## Global Constraints

- Compare **only 5.0.5 and 5.1.1**. No intermediate-release testing or version bisection.
- Use the existing isolated worktree `test/tmp_rovo_issue117`, initially clean and detached at `d12a8b062ee7f9229e3e9ab2a1665f085f1a695b`. Leave the original checkout and its pre-existing untracked `.vscode/` untouched.
- Retain C++17 and the current supported Lua/platform matrix; do not add a system simdjson dependency or change the Lua module's public API merely for diagnostics.
- Vendored `src/simdjson.h` and `src/simdjson.cpp` must come unchanged from the same pinned official release commit. Edit bindings/build files, not vendored code, for project-specific fixes.
- Keep the library's own version/rockspec release tag unchanged unless a separate release decision is approved. Update README's simdjson version and dependency provenance only.
- Every persisted workflow checkpoint has a **cryptographically signed and signed-off Git commit**: `git commit -S -s`. Uppercase `-S` is signature; lowercase `-s` is DCO sign-off. Neither substitutes for the other. Never disable signing, bypass hooks, forge identity, or silently fall back to an unsigned commit.
- A workflow checkpoint is a task deliverable, RED/GREEN boundary, CI evidence update, review correction, or PR-readiness record—not an empty commit for every read-only command. Every additional corrective commit also uses `-S -s`.
- No speculative production fix. A crash fix requires a failing native regression first, minimal implementation, and passing rerun on the same configuration. Already-green characterization tests are useful, but are not RED evidence.
- Use parallel subagents, but never parallel writers in the same worktree/index. Each implementer gets a separate worker worktree and exclusive files. The coordinator alone creates/integrates commits and pushes serially; reviewers are read-only. This explicit isolation adapts the subagent skill's default prohibition on concurrent implementers sharing a checkout.
- No secrets in logs or dump artifacts; diagnostics use synthetic fixtures. Keep dumps bounded, with 7-day artifact retention. Do not run untrusted PR code with `pull_request_target` or write-capable workflow tokens.
- This document is planning only. Wait for plan approval before branch creation, implementation, commits, pushes, PR creation, or triggering CI. During execution, stop on missing authentication/signing or unapproved repository-setting changes; ask the user to resolve prerequisites rather than inspect credentials.
